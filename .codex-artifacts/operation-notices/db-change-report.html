1. 요약

공지사항 페이지를 메모리 mock(zustand store)에서 Supabase 영속 + 감사 로그 적재 경로로 전환했다. 신규 테이블 1개·admin RPC 3종·RLS 정책 1개·인덱스 2개를 admin 운영 네임스페이스에 추가하고 dev DB에 적용했다. 기존 v13/topik_writing/notification 객체는 한 건도 변경되지 않았다(무변경 게이트 통과). 조치(저장·게시/숨김·삭제)는 이제 admin_audit_logs에 OperationNotice 대상으로 사유와 함께 기록된다.

2.2 RLS ADDED

  • ENABLE + FORCE ROW LEVEL SECURITY
  • 정책 operation_notices_admin_select — SELECT, authenticated, private.is_admin(auth.uid())
  • INSERT/UPDATE/DELETE 정책 없음 → 쓰기는 SECURITY DEFINER RPC 단일 경로로만 허용

2.3 admin RPC 3종 ADDED

함수시그니처감사 action가드
admin_save_operation_notice(p_id text, p_notice jsonb, p_reason text) → textnotice_savedunauthenticated → forbidden(private.is_admin) → reason 필수. SECURITY DEFINER, search_path 고정.
admin_toggle_operation_notice_status(p_notice_id text, p_next_status text, p_reason text) → textnotice_status_changed
admin_delete_operation_notice(p_notice_id text, p_reason text) → textnotice_deleted

세 RPC 모두 admin_audit_logs(admin_user_id, action, target_table='OperationNotice', target_id=noticeId, diff, payload)에 사유(payload.reason)와 변경 diff를 기록한다. revoke all from public + grant execute to authenticated.

본 작업은 사용자 승인 “로드맵 전체(다중 세션)” 프로그램의 증분 #1이며, mock→DB 표준 파이프라인(테이블→인덱스→RLS→RPC→seed→서비스 스위치→감사→문서→검증)을 1회 완주해 패턴을 확립했다. 다음 증분(이후 세션, GPT-5.5 멀티 에이전트 병렬): operation 나머지(FAQ·이벤트·정책) → community(게시글·신고, 신고 조치 버그 동반) → commerce(포인트·쿠폰·환불, 서버측 잔액 계산) → system(메타데이터·로그) → Phase 0 감사 로그 화면 실연동(admin_audit_logs 읽기 경로, v13 소유권 협의 필요).
