1. 요약

환불 워크플로(처리 대기/승인/거절)를 Supabase 영속+감사 경로로 전환. 기존엔 v13 payment_history의 status='refunded'를 읽기 전용(항상 '승인')으로 합성했고 supabase 모드 승인/거절 write가 차단돼 있었다. 이제 신규 commerce_refunds 워크플로 테이블 + RPC 2종으로 환불 read를 전환하고 write 차단을 해제했다(기존 객체 변경 0건). 실제 결제 환불 집행(v13 payment_history 갱신)은 v13 소유라 직접 쓰지 않고 intent_only_v13_payment_history_pending로 의도만 기록한다.

2.3 read 전환 · write 차단 해제

  • read: supabase 모드 환불 목록을 payment_history(status='refunded') 합성 → commerce_refunds 워크플로 읽기로 전환(처리 대기/거절 상태가 비로소 표현됨). payments 읽기는 v13 payment_history 그대로(무변경).
  • write: assertMockRefundActionAllowed 차단 해제 → 승인/거절이 RPC로 동작(이전엔 supabase 모드에서 버튼 비활성).
