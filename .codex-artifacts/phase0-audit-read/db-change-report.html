1. 왜 했나 (쉽게)

그동안 12개 도메인의 모든 조치(공지·FAQ·이벤트·정책·게시글/신고·포인트·쿠폰·환불·회원·메타데이터…)는 admin_audit_logs에 "누가·무엇을·왜" 기록해 왔습니다. 그런데 정작 감사 로그 화면은 이 실제 기록을 읽지 않고, 브라우저 메모리의 임시 mock 기록만 보여주고 있었습니다.
이번 작업으로 화면이 실제 DB 감사 로그를 조회하게 되어, 운영 흐름 "검색→상세→조치→감사 로그 확인"의 마지막 고리가 실제로 닫혔습니다.
이 작업이 가능해진 이유: 직전에 admin_audit_logs 소유권을 v13 → topik-ai(admin)로 정정했기 때문입니다. 덕분에 admin이 이 테이블에 조회 인덱스·읽기 RPC를 추가할 수 있게 됐습니다(쓰기·컬럼은 무변경).

3. 화면 연동

  • 읽기 소스 전환: fetchSystemAuditLogsSafe가 데이터소스 분기 — supabase면 admin_list_audit_logs 라이브 단일 소스, mock(또는 VITE_SUPABASE_DISABLED/VITE_SYSTEM_AUDIT_LOGS_SOURCE=mock)이면 기존 스토어 병합.
  • actor 표시명: RPC가 profiles.display_name 우선 → 없으면 uuid → null이면 'system'.
  • 역추적 딥링크: 기존 getTargetRoute가 모든 도메인 Target Type을 원본 화면으로 연결(이미 구축됨).
  • diff/payload: 민감정보 노출 범위 확정 전까지 화면 표시 보류(RPC는 반환하되 행 모델에는 미포함).
