## 선택지와 트레이드오프

### 옵션 1 — 재배정 철회(원안 복원): 분류 = 콘텐츠팀
- **장점**: 원안·역할 경계 회복. 개발은 "입력표를 받아 적재"하는 시스템 역할에 집중. 자가생성 분류의 정합성 책임을 개발이 지지 않음. P2-5가 "남의 일 승인받기"가 아니라 정상적 입력 수령으로 정리됨.
- **단점/비용**: 콘텐츠팀이 466행 분류를 실제로 작성·전달해야 P2 진행 가능 → 일정 의존(실행계획안 R3 리스크 `:471`). 이미 생성·감사한 466행 초안은 "콘텐츠팀 검토용 참고 자료"로 격하(폐기 아님).
- **현 산출물 처리**: 466행 초안 + 적대 감사 결과는 콘텐츠팀에 "초안 제안"으로 제공, 콘텐츠팀이 채택/수정/반려.

### 옵션 2 — 재배정 유지(현 구조): 분류 = 개발 초안 + 콘텐츠팀 승인
- **장점**: 이미 466행 생성·감사 완료, 매몰 작업 활용. 발주서만 발신되면 즉시 진행 가능.
- **단점/비용**: 개발이 콘텐츠 도메인 판단을 계속 보유(사용자가 두 차례 지적한 "개발이 논의할 게 아닌" 영역). P2-5는 "개발이 만든 분류를 콘텐츠팀이 추인"하는 비대칭 구조로 남음. 무게중심 왜곡 지속.
- **즉시 차단 해소 조건**: 발주서 오너 채널 발신 → 10문항 샘플 승인 회신.

### 옵션 3 — 절충
예: 분류 작성 주체는 콘텐츠팀으로 복원하되, 개발 초안을 **공식 시작점**으로 인정(콘텐츠팀이 초안에서 수정/승인). 이는 발주서 품목 1번 문구(`order:12`)가 이미 상정한 모델이며, 사실상 옵션 2의 책임 귀속만 콘텐츠팀으로 옮긴 형태.
