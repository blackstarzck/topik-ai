## 0. 에이전트 공통 규칙 (모든 WP에 적용)

### 0.1 세션 시작 체크리스트

1. 실행계획안 rev3에서 해당 WP가 참조하는 §절을 읽는다.
2. 본 가이드의 해당 WP 항목 전체(가드레일 포함)를 읽는다.
3. 선행 WP의 증적이 `logs/notification-feature-evidence.md`에 PASS로 기록돼 있는지 확인한다 — 없으면 **작업을 시작하지 않고 보고**한다.
4. 작업 공간을 확인한다: topik-ai WP는 `C:\Users\admin\Desktop\workspace\topik-ai`, v13 WP는 `C:\Users\admin\Desktop\workspace\topik-project\v13`. **v13 WP를 topik-ai 작업 공간에서 수행하지 않는다.**

### 0.2 브랜치·커밋

- topik-ai: `feat/notifications` 브랜치. v13: 동명 브랜치를 main 기준으로 생성.
- WP 단위로 커밋한다. 커밋 메시지에 WP ID를 포함한다 (예: `feat(notification): WP1-3 인앱 알림센터 UI`).

### 0.3 금지 사항 (전 WP 공통 가드레일)

- **기존 v13 테이블 DDL 변경 금지** (`profiles`, `notification_settings`, `notification_log` 등) — 계획안 §4.3 결론은 "변경 0건"이다.
- 알림/admin migration을 **`topik_writing_schema_migrations`에 기록 금지** — 반드시 `admin_schema_migrations`(WP0-2 신설) 경로 사용.
- `supabase db reset`을 검증 기준으로 사용 금지 (이 환경에 CLI/Docker 없음) — Management API 스크립트로 검증.
- production Supabase URL에서 실행 금지. service role key·provider secret을 클라이언트 코드/번들에 노출 금지.
- WP0-1(SoT 개정) 승인 전에 어떤 스키마 작업도 시작 금지.
- 화면 동작이 필요한 WP는 **앱을 실제 구동해 확인**하기 전까지 완료로 보고하지 않는다 (계획안 §7.0).
- 스펙에 없는 동작을 임의로 발명하지 않는다 — 미결정(O-*)에 걸리면 작업을 멈추고 결정 요청으로 보고.

### 0.4 휴먼 결정 게이트 (에이전트가 진행 불가, 사용자 결정 필요)

| 게이트 | 내용 | 막히는 WP |

| H-1 | **스키마 소유권 SoT 개정 승인** (양 repo AGENTS.md) | WP0-1 이후 전부 |
| H-2 | O-7 마케팅 동의 저장 방식 | WP0-4(동의 저장소), WP3-3 |

## 1. 페이즈 의존성 지도

```
P0 (SoT·계약·스키마)
  WP0-1 SoT 개정 [H-1] ──┬─→ WP0-2 admin migration 체계 ─→ WP0-5 admin 스키마
                          ├─→ WP0-3 계약 문서 ──────────────↗
                          └─→ WP0-4 v13 스키마 ──────────────→ [게이트 V-0]
P1 (v13 인앱 수직 슬라이스)        ↓
  WP1-1 Edge Function → WP1-2 cron → WP1-3 알림센터+X-09 → WP1-4 B-01 카드+[V-1·V-2]
P2 (topik-ai 관리자 연동)          ↓
  WP2-1 데이터소스 분기 → WP2-2 템플릿/그룹 CRUD → WP2-3 발송·이력·라우트
  WP2-4 legacy 정리(독립) ──────────────────────→ WP2-5 교차 E2E [V-3·V-4]
P3 (이메일)                        ↓
  WP3-1 provider 배선 [H-4] → WP3-2 어댑터+재시도 → WP3-3 동의·상태 표시 [V-5]
P4 (QA·문서 마감)                  ↓
  WP4-1 QA 전수+자동화 → WP4-2 문서 동기화 → WP4-3 게이트 재실행·증적 마감 [V-6]
```

- WP2-1~2-3은 P1과 **병렬 가능** (V-0 통과 후). WP2-4는 언제든 가능. WP2-5만 P1 완료 종속.
- 한 WP = 에이전트 한 세션 분량을 기준으로 한다. 한 세션에 두 WP를 합치지 않는다 (검증·증적이 흐려진다).

## 5. P3 — 이메일 채널 (작업 공간: v13 중심, 일부 topik-ai)

### WP3-1 provider 배선 (휴먼 게이트 H-4)

provider·발신 도메인 결정(O-1) → secret을 Edge Function 환경변수로 배선 → 테스트 계정 수신 1건 확인. **결정 전 진행 불가.**

### WP3-2 email 어댑터 + 재시도 (v13)

### WP3-3 동의 평가·상태 표시 (v13 + topik-ai)

marketing 발송 전 수신 동의 평가(H-2 결정 반영, 비동의 `opted_out`), 관리자 나에게 보내기 email 추가, X-09 "발송 준비 중" → 채널 상태 표시(email=활성, push/zalo=준비 중).

검증: QA N-OPT-04, N-EML-07(수신거부 — 미구현 시 UNDEFINED 에스컬레이션), N-EML-08·09(P2 항목). **게이트 V-5 PASS로 P3 종료.**
