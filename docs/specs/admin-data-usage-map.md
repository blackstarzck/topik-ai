# TOPIK AI Admin 관리 데이터 - B2C 노출 맵

이 문서는 관리자 페이지에서 다루는 테이블/정적 데이터/운영 입력 데이터가 B2C 화면 어디에 노출되고 어떻게 사용되는지 추적하기 위한 기준 문서입니다.

## 1) 목적

- 관리자 데이터 변경이 B2C 어디에 영향을 주는지 빠르게 판단
- 운영/기획/개발/QA가 같은 데이터 기준으로 협업
- placeholder 상태의 메뉴도 향후 B2C 연결 지점을 미리 기록

## 2) 기록 규칙

- 관리자 화면에서 생성, 수정, 삭제, 상태 변경이 가능한 데이터는 모두 이 문서의 대상입니다.
- B2C 실제 코드나 기획서로 확인되지 않은 노출 위치는 추정으로 표시합니다.
- 한 데이터가 여러 B2C 화면에 쓰이면 대표 노출 위치와 보조 노출 위치를 함께 적습니다.
- 내부 운영용 데이터는 `내부 전용`으로 명시합니다.

## 3) 노출 상태 정의

- `확인됨`: 현재 기준으로 B2C 노출 위치가 구현 또는 합의 문서로 확인됨
- `운영상 추정`: 관리자 도메인과 기능상 연결은 명확하지만, B2C 실제 구현/문서 확인은 아직 없음
- `내부 전용`: 관리자/배치/감사 목적으로만 사용되고 B2C 직접 노출이 없음
- `노출 예정`: 메뉴 자리는 확보했지만 B2C 노출 구조가 아직 정의되지 않음

### Assessment 문항 버전·사용자 상태별 노출

- SoT: `docs/architecture/writing-question-version-policy.md`
- 관리자 `topik_writing_question_import` 불변 내용 버전과 `question_source_map.canonical_import_id` 현재 버전 포인터는 관리자 이력·신규 사용자 노출의 원천입니다. 관리자 이력은 `mapping_status='promoted'`만 포함하며 `raw`·`held`·`metadata_only`·이상 응답은 인박스에서 확인합니다. 인박스 `is_latest`는 마지막 수신 원문 표시일 뿐 사용자 현재 버전이 아닙니다.
- 신규 풀이·북마크·임시저장은 `question_id`의 현재 버전을 사용하고, 제출 완료·채점·피드백·과거 결과는 제출 시점의 import ID/hash/문항 스냅샷을 사용합니다.
- B2C 노출 상태: `확인됨`(현재 버전 포인터, 제출 스냅샷 기반 구조), `내부 전용`(관리자 버전 수정 횟수·이력·과거 payload UI), `구현/교차 검증 필요`(북마크·활성 임시저장 최신화와 호환성 차단).
- 관리자 이력 1차 UI는 버전별 전체 payload 조회까지 제공하며 자동 필드 diff는 후속 갭입니다. 과거 버전 복원·재활성화는 정책 비범위입니다.
- 사용자에게 일반 문항 수정 알림이나 버전 번호를 노출하지 않으며, 관리자 운영 값(`service_status`, 태그, 기관 노출)은 외부 문항 내용 버전과 분리해 보존합니다.

## 5) 운영 메모

- 이 문서는 관리자 프론트엔드 저장소 기준으로 작성되며, B2C 실제 구현 저장소가 없으면 `운영상 추정`과 `노출 예정`을 사용합니다.
- `운영상 추정` 상태의 항목은 B2C 팀과 합의가 끝나면 `확인됨`으로 승격합니다.
- 새 테이블 또는 새 정책 데이터가 생기면 같은 작업에서 이 문서에 반드시 추가합니다.

- read source는 v13 소유 `profiles`와 `auth.users` 조인, `writing_submissions` 집계다. 주요 필드는 `profiles.id/display_name/nickname/app_role/plan_label/status/created_at`, `auth.users.email/last_sign_in_at`, `writing_submissions`의 제출 수와 최근 제출 시각이다.

## 2026-07-09 Users 성별/전화번호 표시와 회원 정보 내보내기 데이터 사용 보강

- `Users > 회원 목록`과 `Users > 회원 상세 > 프로필`은 `profiles.gender`를 관리자 표시값으로 읽어 성별을 노출합니다. B2C 연결은 마이페이지 프로필의 성별 후보로 `운영상 추정`을 유지합니다.
- `Users > 회원 목록`은 `profiles.phone_country_code` + `profiles.phone_number`를 admin helper에서 조합하고 `get_admin_users(..., affiliation)`의 `phone_masked` 반환값만 표시합니다. optional legacy `profiles.phone`은 JSON fallback일 뿐 직접 참조하지 않습니다. 마스킹 규칙은 앞 3자리와 끝 4자리만 남기고 중간 자리는 `****`로 숨깁니다.
- `Users > 회원 상세 > 프로필`은 단건 운영 확인 목적의 `get_admin_user(target_id)` 결과에서 split phone 조합값을 우선 표시하고, 없으면 `phone_masked`로 fallback합니다. B2C 연결은 마이페이지 프로필의 전화번호 후보로 `운영상 추정`을 유지합니다.
- `Users > 회원 정보 내보내기`는 `admin_export_users(..., p_scope, p_selected_user_ids, 목록 필터, p_selected_column_keys)` RPC가 제공하는 내부 운영 반출 기능입니다. 기본 범위는 현재 목록 조건이고, 선택 행이 있으면 선택 회원만 내보낼 수 있습니다. 파일에는 선택한 컬럼만 포함되며, 사용자 ID는 필수 고정입니다. 전화번호 컬럼을 제외하면 원문 포함 옵션은 비활성화되고 서버에는 `include_full_phone=false`로 전달합니다.
- 회원 정보 내보내기 감사 로그 payload에는 사유, 행수, scope, 원문 포함 여부, 선택 컬럼 key, 선택 행 수, 필터 적용 여부와 안전한 필터 요약만 남깁니다. 검색어 원문, 성별 값, 전화번호 값, 내보낸 파일 내용은 저장하지 않습니다.
- 회원 정보 내보내기 감사 로그(`User + batch:{uuid}`, action `users_exported`)는 내부 전용 운영 증적이며 B2C 화면에 직접 노출하지 않습니다.
