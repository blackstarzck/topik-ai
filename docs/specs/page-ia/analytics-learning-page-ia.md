# Analytics > 학습 분석 상세 IA

## 1. 문서 목적

- 학습 분석 화면의 운영 목적, 데이터 블록, 조치 흐름을 같은 기준으로 정리합니다.
- TOPIK 쓰기(51~54번) 전체 사용자 학습 지표를 기간별로 검수하는 화면의 계약을 고정합니다.
- 운영 기본 흐름 검색 -> 상세 -> 조치 -> 감사 로그 확인 또는 편집형 화면의 작성/수정 -> 확인 -> 발행 -> 감사 로그 확인을 유지합니다.

## 3. 페이지 목표와 비목표

### 목표

- TOPIK 쓰기 학습 지표(활성 학습자, 제출량, 피드백 완료율, 점수, 열람률, 소요 시간)를 기간별로 검수합니다.
- 문항(51~54)·점수 분포·취약 평가 차원·태그별 성과를 콘텐츠/운영 개선 우선순위 판단에 사용합니다.

### 비목표

- 개인 학습자 단위 데이터를 노출하지 않습니다(개인 식별자 미반환 — 회원 상세 학습 현황 탭이 담당).
- 기존 통계 개요의 운영 지표(가입/신고/알림/매출)를 대체하지 않습니다.
- 답안 원문·문장별 첨삭 등 민감 본문 데이터는 다루지 않습니다.

## 4. 운영자 사용 시나리오

- 시나리오 1: 운영자가 기간(7/30/90일/전체)을 선택해 학습 활성 사용자와 제출량, 피드백 완료·실패율 추이를 확인합니다.
- 시나리오 2: 문항별 성과와 점수 분포에서 저성과 문항/구간을 찾아 평가 관리 화면에서 해당 문항을 검수합니다.
- 시나리오 3: 취약 평가 차원과 태그별 성과로 학습 콘텐츠 보강 우선순위를 정리해 콘텐츠 파이프라인에 반영합니다.

| --- | --- | --- | --- | --- | --- |

## 6. 데이터 블록 정의

### 상단 요약 데이터
- 학습 활성 사용자 수(기간 내 study_events 1건 이상 — 로그인 기준 아님, 통계 개요의 "활성 사용자(로그인)"와 정의 구분)
- 제출 수/제출 사용자 수, 피드백 완료·대기·실패와 완료율/실패율
- 평균 점수(100점 환산, 행별 score_max 기준 정규화)
- 피드백 열람률(feedback_viewed 이벤트 기준), 재제출 수
- 평균 소요 시간(writing_submission_metrics; 수집 0건이면 "미수집" — 0분으로 렌더 금지)
- 피드백 처리 시간(중앙값 병기 — 재동기화 이력로 평균이 부풀 수 있음)

### 검색/선택 데이터
- 기간(period: 7d/30d/90d/all, URL 쿼리 복원)

### 본문 데이터
- 문항별 성과(51~54), 점수 분포(0-19/20-39/40-59/60-79/80-100), 취약 평가 차원(차원 점수 표본 수 병기), 태그별 성과 상위 12개

### 상세 데이터
- 별도 상세 패널 없음. 개인 단위 상세는 Users > 회원 상세 > 학습 현황 탭이 담당합니다.

## 11. URL/상태 복원

- 기본 라우트: /analytics/learning
- 필수 쿼리 파라미터 후보: period(7d/30d/90d/all, 기본 30d)
- Drawer/Modal 복원 여부: 해당 없음
- 유지되어야 하는 상태: 기간 선택만 복원합니다.

## 12. 네트워크 상태와 fail-safe

- pending: KPI 카드/테이블 loading 상태를 표시합니다.
- success: 정상 결과를 렌더링합니다.
- empty: 집계 값이 없으면 0/미수집을 구분해 표기합니다(빈 화면으로 두지 않음).
- error: 오류 메시지와 재시도 버튼을 Alert로 노출합니다.
- 요청 취소/재시도: 기간 변경 시 이전 요청 abort, 실패 시 재시도 버튼.
