# System > 백업 관리 상세 IA

## 1. 목적

- `topik-prod` 자동 백업과 월간 복원 점검 상태를 관리자에게 조회 전용으로 제공합니다.
- localhost에서는 `topik-dev`에 저장된 운영 보고 복사본을 보여주며, 실제 백업 대상이 `topik-prod`임을 명확히 안내합니다.
- 자동 작업은 관리자 조치가 아니므로 `시스템 로그`로 추적하고 `감사 로그`에는 기록하지 않습니다.

## 2. 페이지 메타

| 항목 | 내용 |
| --- | --- |
| 모듈 | System |
| 페이지명 | 백업 관리 |
| 라우트 | `/system/backups` |
| 현재 상태 | 구현됨 |
| 페이지 유형 | 조회 전용 목록 + 상세 Drawer |
| 주요 권한 | `system.backups.read` |
| 주요 운영자 | 슈퍼 관리자, 권한을 별도로 받은 운영 담당자 |
| 연관 문서 | `docs/runbooks/topik-prod-onprem-backup.md`, `docs/specs/admin-data-contract.md`, `docs/specs/admin-page-tables.md` |

## 3. 화면 구조

| 영역 | 표시 내용 | 액션 |
| --- | --- | --- |
| 개발환경 안내 | 운영 백업 상태의 개발환경 복사본, 마지막 복사 시각 | 없음 |
| 상단 요약 | 현재 상태, 마지막 전체 성공, 최근 7일 성공률, 디스크 사용률, 마지막 복원 점검 | 없음 |
| 검색 | 기간, 전체 결과, 백업 대상, 작업 번호 | 조건 변경, 초기화 |
| 목록 | 시작·종료, 전체·대상별 결과, 용량, 실행 시간, 디스크 사용률 | 행 선택 |
| 상세 Drawer | 검사 결과, 정리된 오류 분류, 연결된 시스템 로그 | 시스템 로그 이동 |

개발환경 안내는 localhost에서 `topik-dev`를 읽을 때만 표시합니다. 운영 배포는 `topik-prod` 원본 보고를 읽습니다.

## 4. 상태와 경고

| 구분 | 화면 표시 | 기준 |
| --- | --- | --- |
| 실행 | 진행 중 | 시작 보고는 있고 완료 보고는 없음 |
| 실행 | 정상 | 데이터베이스와 파일 저장소 모두 성공 |
| 실행 | 부분 실패 | 두 대상 중 한쪽만 실패 |
| 실행 | 실패 | 두 대상 실패 또는 전체 실패 |
| 실행 | 지연 | 시작 뒤 2시간이 지나도 미완료 |
| 실행 | 기록 없음 | 보고 이력 없음 |
| 최신성 | 주의 | 마지막 전체 성공 후 8시간 경과 |
| 최신성 | 실패 | 마지막 전체 성공 후 12시간 경과 |
| 디스크 | 주의 | 사용률 80% 이상 |
| 디스크 | 위험 | 사용률 90% 이상 |
| 복원 | 경고 | 성공 기록이 35일 이상 없거나 최근 점검 실패 |

## 5. 권한과 보안

- 모든 활성 관리자는 대시보드 요약을 볼 수 있습니다.
- 상세 목록과 Drawer는 `system.backups.read` 권한이 있어야 합니다.
- 브라우저의 직접 쓰기와 백업·복원 실행 버튼은 제공하지 않습니다.
- 파일명, 저장 경로, 회원 정보, 연결 정보, 비밀값, 원문 오류를 저장하거나 표시하지 않습니다.
- 완료 자동 작업은 연결된 `시스템 로그`에서 확인합니다. `감사 로그` 링크는 제공하지 않습니다.

## 6. URL 복원

- 검색과 선택 상태는 `startDate`, `endDate`, `result`, `target`, `keyword`, `page`, `runId`로 복원합니다.
- 페이지 크기는 20건으로 고정합니다.
- 행을 선택하면 `runId`가 주소에 남아 새로고침 뒤 같은 상세를 다시 엽니다.

## 7. 네트워크 상태와 장애 격리

- 대기: 현재 화면 안에서 로딩 상태를 표시합니다.
- 성공: 요약·목록·상세를 표시합니다.
- 빈 결과: 기록 없음 안내와 검색 초기화 방법을 제공합니다.
- 오류: 페이지 안에서 오류와 재시도를 표시하고 마지막으로 확인된 요약이 있으면 유지합니다.
- 백업 조회 실패가 다른 Dashboard/System 화면 전체를 중단시키지 않아야 합니다.

## 8. 비목표와 잔여 위험

- `topik-dev` 데이터베이스나 파일 저장소를 자동 백업하지 않습니다.
- 관리자 화면에서 백업 파일을 다운로드하거나 복원하지 않습니다.
- 외부 저장소와 외장 디스크를 사용하지 않으므로 Supabase 원본과 온프레미스 디스크가 동시에 손상되면 복구할 수 없습니다.
- 2026-07-21 첫 완전 백업과 격리 복원은 통과했습니다. 수신 API 배포 후 운영/개발 화면 반영과 24시간 동안 4회 연속 보고가 확인되기 전에는 관리자 연동 완료로 보지 않습니다.
