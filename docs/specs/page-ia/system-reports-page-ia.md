# System > 사용자 리포트 상세 IA

## 1. 목적

- 학습자 앱에서 접수된 오류 신고·문의·제안을 관리자가 조회하고, 필요할 때만 단건으로 삭제합니다.
- 접수 경로와 저장 계약은 학습자 앱이 정의했고 이 저장소가 인수했습니다. 관리자 화면은 정본 테이블을 변형하지 않고 읽기와 단건 삭제만 추가합니다.
- 삭제는 관리자 조치이므로 `감사 로그`에 사유와 함께 기록하고, 감사 기록에는 제출자 식별 정보를 남기지 않습니다.

## 2. 페이지 메타

| 항목 | 내용 |
| --- | --- |
| 모듈 | System |
| 페이지명 | 사용자 리포트 |
| 라우트 | `/system/reports` |
| 현재 상태 | 구현됨 |
| 페이지 유형 | 조회 목록 + 상세 Drawer + 단건 삭제 |
| 주요 권한 | `system.reports.read`, `system.reports.delete` |
| 주요 운영자 | 슈퍼 관리자 |
| 연관 문서 | `docs/specs/admin-data-contract.md`, `docs/specs/admin-page-tables.md`, `docs/specs/admin-action-log.md`, `docs/architecture/shared-supabase-schema-ownership.md` |

## 3. 화면 구조

| 영역 | 표시 내용 | 액션 |
| --- | --- | --- |
| 상단 안내 | 접수 내용에 제출자 이메일과 자유 서술이 포함된다는 취급 주의, 삭제 비가역 안내 | 없음 |
| 검색 | 접수 기간, 유형, 통합 검색(접수번호·제목·본문·이메일) | 조건 변경, 초기화 |
| 목록 | 접수 시각, 접수번호, 유형, 제목, 회신 이메일, 발생 화면 | 행 선택 |
| 상세 Drawer | 접수 정보, 접수 내용(제목·본문), 진단 정보 | 감사 기록 이동, 리포트 삭제 |
| 삭제 확인 | 대상 접수번호, 필수 사유 입력 | 삭제 실행, 취소 |

## 4. 데이터 계약

| 항목 | 내용 |
| --- | --- |
| 저장 테이블 | `private.system_reports` (정본 소유는 학습자 앱, 적용 장부는 이 저장소의 `admin_schema_migrations`) |
| 접수 RPC | `public.submit_system_report` — `service_role` 전용. 관리자 화면은 호출하지 않습니다. |
| 조회 RPC | `public.admin_list_system_reports` — `system.reports.read` 보유자만. 페이지네이션과 총건수를 함께 반환합니다. |
| 삭제 RPC | `public.admin_delete_system_report` — platform_admin 전용, 사유 필수, 접수번호를 반환합니다. |
| 감사 기록 | Target Type `SystemReport`, Target ID = 접수번호, Action `system_report_deleted` |
| 감사 payload | 사유, 접수번호, 유형, 언어, 발생 화면, 브라우저·OS·기기, 앱 버전, 로그인 여부, 접수 시각 |

## 5. 비목표

- 정본 테이블에 상태·담당자·처리 메모 컬럼이나 트리거를 추가하지 않습니다. 접수 항목 집합은 학습자 앱이 정한 그대로 유지합니다.
- 자동 보관 기한이나 일괄 삭제 작업을 만들지 않습니다. 보관은 무기한이고 삭제는 승인된 단건 처리만 허용합니다.
- 상태 변경, 담당자 배정, 외부 알림 발송은 이 페이지의 범위가 아닙니다.
- 감사 payload에 제출자 이메일·제목·본문·사용자 식별자를 담지 않습니다. `감사 로그`는 조회 권한이 더 넓어 삭제가 개인정보를 감사 테이블로 옮기는 결과가 되면 안 됩니다.

## 6. 권한과 접근 통제

| 권한 | 위험도 | 범위 |
| --- | --- | --- |
| `system.reports.read` | medium | 접수 내용과 진단 정보 조회 |
| `system.reports.delete` | high | 사유와 함께 단건 영구 삭제 |

- 두 권한은 권한 카탈로그에만 정의하고 별도 역할에 기본 부여하지 않습니다. 슈퍼 관리자만 전체 권한을 자동으로 갖습니다.
- 조회 권한이 없으면 페이지 진입 시 403 안내를 표시하고, 메뉴에도 노출하지 않습니다.
- 삭제 권한이 없으면 상세 Drawer에 삭제 버튼을 표시하지 않으며, RPC도 platform_admin 여부를 다시 확인합니다.

## 7. 검증

- 조회·삭제 RPC의 소유자·SECURITY DEFINER·`search_path`·역할별 EXECUTE를 적용 후 카탈로그로 확인합니다.
- 접수 → 목록 조회 → 삭제 → 감사 기록 왕복을 롤백 트랜잭션으로 확인하고, 감사 payload에 제출자 식별 정보가 없는지 함께 검사합니다.
- 미인증 호출, 사유 누락, 잘못된 유형 필터, `anon` 실행 권한 부재를 각각 확인합니다.
