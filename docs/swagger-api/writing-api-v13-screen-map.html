v13 Writing 화면 API 연결 지도

Swagger의 Writing API를 v13 사용자 화면 기준으로 쉽게 풀어 정리한 문서입니다. 기준일은 2026-06-17이며, 실제 구현 전에는 Swagger를 다시 확인해야 합니다.

한 줄 결론

현재 v13 쓰기 화면은 대부분 Supabase를 직접 사용합니다. 외부 API 중 지금 코드에 다시 남겨둔 것은 POST /api/writing/save-draft 자동저장 호출 helper뿐입니다. 화면에 실제 연결된 상태는 아직 아닙니다.

전체 Swagger 계약(request header, parameter, request body, response, example, auth, error code)은 같은 폴더의 openapi-reference.md에 정리되어 있습니다. 이 HTML은 전체 API 명세서가 아니라 v13 Writing 화면에서 어떤 API를 어디에 연결할지 보는 화면 기준 지도입니다.

자동저장 helper 있음 API 호출 함수만 존재
문제 가져오기 미연결 현재 Supabase에서 로드
최종 제출 미연결 현재 Supabase RPC 사용

화면 기능별 연결 판단

사용자 화면 기능 Swagger API 현재 v13 상태 쉬운 설명
51~54번 문제 보여주기 GET /api/writing/tasks/{task_type} 아직 미연결 화면에 문제 제목, 지문, 조건, 그래프/표를 보여줄 때 쓰는 후보 API입니다. 현재 v13은 getWritingProblem()으로 Supabase problems 데이터를 직접 읽습니다.
작성 중 자동저장 POST /api/writing/save-draft helper만 있음 사용자가 쓰는 중간 답안을 서버에 저장하는 API입니다. 현재 저장 helper는 src/lib/writing-api/save-draft.ts에 있지만, 실제 화면은 아직 기존 Supabase writing_drafts 흐름을 사용합니다.
최종 제출 POST /api/writing/submit 아직 미연결 답안을 제출하고 AI 채점으로 넘길 때 쓰는 후보 API입니다. 현재 v13은 submitWritingAction()과 Supabase RPC submit_writing_with_feedback를 사용합니다.
채점 상태 확인 GET /api/evaluation/{submission_id} 아직 미연결 제출 후 “채점 중 / 완료 / 실패” 상태를 확인할 때 쓰는 후보 API입니다.
피드백 보기 GET /api/evaluation/{submission_id}/feedback 아직 미연결 점수, 항목별 피드백, 첨삭, 모델 답안을 보여줄 때 쓰는 후보 API입니다. 현재 v13은 Supabase 피드백 테이블을 읽습니다.
자동저장 답안 다시 불러오기 Swagger에 전용 API 없음 API 공백 저장은 할 수 있지만, 전체 답안 텍스트를 다시 불러오는 API가 Swagger에 없습니다. GET /api/writing/history?status=draft는 미리보기만 제공하므로 에디터 복구에는 부족합니다.

자동저장 API만 남긴 현재 코드

현재 저장 helper의 역할은 아래 하나입니다.

POST /api/writing/save-draft
Authorization: Bearer <supabase_access_token>
Content-Type: application/json

{
  "task_type": "Q54",
  "task_id": "task-id",
  "text": "current draft text"
}

응답은 submission_id, saved_at, character_count를 기대합니다.

구현 전 결정 필요

자동저장을 외부 API로 완전히 바꾸려면 “저장된 전체 답안을 어떻게 다시 불러올지”가 먼저 정해져야 합니다. 지금 Swagger 기준으로는 full draft restore API가 없기 때문에, 기존 Supabase writing_drafts를 계속 읽거나 백엔드에 draft detail API를 추가해야 합니다.
