## 1. 목적

- 운영 백업과 복원 점검의 관리자 조회 계약을 고정합니다.
- 이 데이터가 사용자 화면에 노출되지 않는 내부 운영 증적임을 명확히 합니다.
- 운영 원본과 localhost 조회 복사본의 차이를 기록합니다.

## 2. 페이지 요약

| 항목 | 내용 |
| --- | --- |
| 라우트 | `/system/backups` |
| 주요 권한 | `system.backups.read` |
| 실제 백업 대상 | `topik-prod` 데이터베이스와 전체 파일 저장소 |
| 운영 화면 데이터 | `topik-prod`에 저장된 보고 원본 |
| localhost 화면 데이터 | `topik-dev`에 독립 저장된 같은 보고의 복사본 |
| B2C 영향 | 없음, 내부 전용 |

`topik-dev`에는 파일이나 데이터베이스 덤프가 저장되지 않습니다. 상태·시각·개수·용량·검사 결과 같은 비민감 보고만 저장됩니다.

## 3. 가능한 작업

| 기능 | 성격 | 결과 | 감사 로그 |
| --- | --- | --- | --- |
| 요약 조회 | 조회 | 현재 상태와 경고 확인 | 불필요 |
| 실행 검색 | 조회 | 기간·결과·대상별 이력 확인 | 불필요 |
| 상세 조회 | 조회 | 검사와 정리된 오류 확인 | 불필요 |
| 시스템 로그 이동 | 조회 | 자동 작업의 기술 이벤트 확인 | 불필요 |

백업·복원 실행, 파일 다운로드, 데이터 수정 기능은 제공하지 않습니다.

## 4. 관리 데이터

| 엔티티 | 원본 | 용도 | B2C 상태 |
| --- | --- | --- | --- |
| BackupRun | `admin_backup_runs` | 한 번의 전체 실행 결과 | 내부 전용 |
| BackupComponentResult | `admin_backup_component_results` | 데이터베이스·파일 저장소별 결과 | 내부 전용 |
| RestoreDrill | `admin_restore_drills` | 월간 격리 복원 점검 | 내부 전용 |
| BackupReportEvent | `admin_backup_report_events` | 중복 방지와 마지막 보고 수신 시각 | UI 최소 노출, 내부 전용 |
| SystemLog | `system_logs` | 자동 완료 기술 로그 | 내부 전용 |

## 5. 운영 원본과 개발 복사본

- 같은 보고 본문을 운영 원본과 개발 복사본에 각각 전송합니다.
- 각 전송은 서로 다른 공유 비밀값과 대상이 포함된 서명을 사용합니다.
- 두 전송은 별도 대기열에서 재시도하므로 개발 복사 실패가 운영 기록이나 실제 백업을 실패로 바꾸지 않습니다.
- localhost는 개발환경 복사본 안내와 마지막 복사 시각을 표시합니다.
- 운영 배포는 복사본 안내를 표시하지 않고 `topik-prod` 원본을 읽습니다.

## 6. 사용자 화면 동기화

| 사용자 화면 | 영향 상태 | 설명 |
| --- | --- | --- |
| 직접 연결 화면 없음 | 내부 전용 | 백업 상태는 사용자 기능과 데이터에 반영되지 않음 |

## 7. 권한과 로그

- 상세 읽기는 `system.backups.read`로 제한합니다.
- 브라우저 직접 쓰기는 허용하지 않습니다.
- 자동 작업은 `시스템 로그`에 연결하고 `감사 로그`에는 기록하지 않습니다.
- v13 소유 테이블과 사용자 데이터 구조는 변경하지 않습니다.
