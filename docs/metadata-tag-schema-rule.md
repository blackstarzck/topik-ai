# **1\. 메타데이터와 태그의 차이**

| 핵심 정의 메타데이터는 문제의 바뀌지 않는 사실 정보입니다. 태그는 운영 중 바뀔 수 있는 추천·노출용 표시입니다. |
| :---- |

| 구분 | 메타데이터 | 태그 |
| :---- | :---- | :---- |
| 쉽게 말하면 | 문제의 신분증 | 문제에 붙이는 운영 스티커 |
| 바뀌는 정도 | 문제 내용이 바뀌지 않으면 거의 바뀌지 않음 | 추천 정책, 운영 판단, 검수 상태에 따라 바뀔 수 있음 |
| 예시 | 문제\_번호(item\_number), 글\_유형(text\_type), 주제\_종합(topic\_main), 구체상황(scenario\_type), 사용문법(grammar\_patterns), 자료\_유형(data\_type), 글\_구성(required\_structure) | 대표 문제, 오답 후 추천, 복습용, 노출 제외, 검수 필요 |
| 담당 | 콘텐츠팀이 확인하고, 개발팀이 DB와 추천 규칙에 사용 | 콘텐츠팀과 운영자가 선별·추가·제거 |
| 추천에서의 역할 | 문제끼리 왜 연결되는지 판단하는 기준 | 서비스에서 언제 보여 줄지 조정하는 기준 |

따라서 문제 데이터는 한 덩어리로 관리하지 않고, “문제 본문”, “메타데이터”, “태그”, “검수·관리 정보”로 나누어 보는 것이 좋습니다.

# **2\. 태그 설명**

태그는 문제의 사실 정보가 아니라, 서비스를 운영하면서 “이 문제를 어떻게 사용할지” 표시하는 값입니다. 태그는 바뀔 수 있으므로 문제 테이블 안에 고정 컬럼으로 박아 두기보다 별도 태그 테이블에서 관리하는 것을 권장합니다.

## **2.1 태그를 붙이는 기준**

* 학습자에게 이 문제를 언제 보여 줄지 생각합니다.  
* 오답 후 다시 보여 줄 문제인지, 처음 진입용 문제인지, 복습용 문제인지 판단합니다.  
* 비슷한 문제가 너무 많으면 반복 방지 태그를 붙입니다.  
* 표현이나 난이도가 애매하면 검수 필요 또는 표현 주의 태그를 붙입니다.  
* 문제 자체의 사실 정보는 태그에 넣지 않고 메타데이터에 넣습니다.

## **2.2 태그로 관리할 수 있는 칼럼**

| 태그 칼럼 | 설명 | 값 예시 |
| :---- | :---- | :---- |
| 서비스\_노출상태 | 현재 서비스에 노출할지 판단합니다. | 노출 가능, 노출 제외, 내부 테스트 |
| 추천\_사용상태 | 추천 엔진에서 사용할 수 있는지 판단합니다. | 추천 사용, 추천 제외, 오답 추천만 사용 |
| 대표문제\_여부 | 해당 유형을 대표하는 좋은 문제인지 표시합니다. | 대표 문제, 일반 문제 |
| 추천목적\_태그 | 이 문제가 어떤 추천 상황에 적합한지 표시합니다. | 첫 진입용, 오답 후 추천, 복습용, 심화용 |
| 반복방지\_태그 | 연속 노출 시 지루할 수 있는 문제를 표시합니다. | 같은상황주의, 같은정답주의, 같은자료형주의 |
| 학습흐름\_태그 | 문제 순서를 잡을 때 참고합니다. | 기초 확인, 같은 기능 반복, 다음 단계 |
| 운영주의\_태그 | 콘텐츠 운영상 주의가 필요한 문제를 표시합니다. | 검수 필요, 표현 주의, 난이도 애매 |
| 콘텐츠팀\_메모 | 공급/콘텐츠팀이 전달한 운영 참고사항을 적습니다. | “비슷한 상담 시간 변경 문제가 많음” |

## **2.3 태그를 추천 규칙에서 쓰는 방식**

추천 엔진은 먼저 메타데이터로 문제를 찾고, 마지막에 태그로 운영 판단을 반영합니다.

* 대표 문제, 복습용, 오답 후 추천 태그가 있으면 추천 점수를 올립니다.  
* 노출 제외, 검수 필요, 추천 제외 태그가 있으면 추천 후보에서 제외합니다.  
* 같은상황주의, 같은정답주의, 같은자료형주의 태그가 있으면 연속 노출을 피합니다.

# **4\. 메타데이터 설명**

메타데이터는 문제가 원래 가지고 있는 사실 정보입니다. 문제의 본문, 정답, 글\_유형(text\_type), 주제\_종합(topic\_main), 구체상황(scenario\_type), 사용문법(grammar\_patterns), 자료\_유형(data\_type), 글\_구성(required\_structure)처럼 문제 자체를 설명하는 값입니다. 원칙적으로 문제 내용이 바뀌지 않으면 메타데이터도 바뀌지 않습니다.

단, 처음 입력한 메타데이터가 잘못되었거나 주제 분류가 틀린 경우에는 “운영 변경”이 아니라 “오류 수정”으로 고칠 수 있습니다.

표기 방식: 이 문서의 메타데이터 칼럼명은 콘텐츠팀이 이해하기 쉬운 한국어명과 개발팀이 사용할 영어명을 함께 보여 주기 위해 한국어명(영어명) 형식으로 표기합니다. 예: 문제\_ID(question\_id), 주제\_종합(topic\_main), 글\_유형(text\_type).

## **4.1 51·52·53·54번 메타데이터 설계 원칙**

| 권장 구조 모든 문제에 공통으로 들어가는 메타데이터는 동일하게 유지합니다. 하지만 51·52·53·54번은 문제 유형이 다르므로, 번호별로만 의미 있는 세부 메타데이터는 따로 둡니다. |
| :---- |

| 구분 | 무엇을 담나 | 예시 |
| :---- | :---- | :---- |
| 공통 메타데이터 | 51·52·53·54번 모두에 필요한 정보 | 문제\_ID(question\_id), 문제\_번호(item\_number), 주제\_종합(topic\_main), 검수상태(review\_status) |
| 51번 세부 메타데이터 | 실용문 빈칸 완성에 필요한 정보 | 빈칸\_수(blank\_count), 빈칸\_역할(blank\_role), 대표정답(canonical\_answer) |
| 52번 세부 메타데이터 | 문장·문단 완성에 필요한 정보 | 연결\_기능(connection\_function), 앞문장\_단서(clue\_before\_text), 허용답안\_범위(answer\_scope\_type) |
| 53번 세부 메타데이터 | 자료 해석형 쓰기에 필요한 정보 | 자료\_유형(data\_type), 비교대상\_수(comparison\_target\_count), 요구\_글구성(required\_structure) |
| 54번 세부 메타데이터 | 논술형 쓰기에 필요한 정보 | 글쓰기\_유형(essay\_type), 요구\_관점(stance\_requirement), 글\_구성(required\_structure) |

DB 테이블은 문제 번호별로 나눕니다. 즉, 51번 문제는 51번 테이블, 52번 문제는 52번 테이블, 53번 문제는 53번 테이블, 54번 문제는 54번 테이블에 들어갑니다. 다만 네 테이블에 들어가는 공통 컬럼명은 최대한 같게 유지해야 추천 로직을 만들기 쉽습니다.

## **4.2 전체 공통 메타데이터**

아래 값은 51·52·53·54번 모두에 공통으로 들어가는 값입니다. 문제 번호가 달라도 추천의 1차 필터로 사용할 수 있습니다.

| 공통 칼럼명(영어명) | 설명 | 예시 |
| :---- | :---- | :---- |
| 문제\_ID(question\_id) | 문제를 구분하는 고유값입니다. | topik-writing-51-0001 |
| 시험\_영역(section) | 시험과 영역을 표시합니다. | TOPIK 쓰기 |
| 문제\_번호(item\_number) | TOPIK 쓰기 번호입니다. | 51, 52, 53, 54 |
| 목표\_급수(target\_level) | 문제가 목표로 하는 수준입니다. | TOPIK 3급, TOPIK 4급, TOPIK 5급 |
| 난이도\_단계(difficulty\_level) | 표준 교육과정을 참고해 나누는 추천 계산용 내부 난이도입니다. | 1\~6 |
| 문제\_유형명(question\_type\_name) | 사람이 읽는 문제 유형입니다. | 빈칸 완성형, 자료 설명형, 논술형 |
| 주제\_종합(topic\_main) | 고정 주제 목록 중 하나입니다. | 주거와 환경, 교육, 여가와 오락 |
| 주제\_세부내용(topic\_detail) | 종합 주제 안의 세부 항목입니다. | 방, 학교 교육, 영화ㆍ공연 |
| 보조\_주제(secondary\_topic) | 부주제가 있을 때만 입력합니다. | 교통 / 교통수단 |
| 글의\_목적(speech\_act) | 문제가 요구하는 말하기/쓰기 목적입니다. | 문의, 요청, 설명, 비교, 주장 |
| 글\_유형(text\_type) | 글의 성격과 구체적 종류를 한 칼럼에서 함께 관리합니다. | 개인적 글/요청 이메일, 공개적 글/문의 게시글, 설명문/그래프 설명문 |
| 관계(relation) | 글쓴이와 독자/수신자의 관계입니다. | 개인 → 기관 담당자, 기관 → 학생 |
| 구체상황(scenario\_type) | 문제 상황을 짧게 분류한 값입니다. | 상담 시간 조정 요청, 도서관 이용 시간 조사 |
| 상황요약(situation\_summary) | 문제가 다루는 상황을 한 문장으로 설명합니다. | 상담 시간을 뒤로 미루고 싶은 상황 |
| 핵심\_학습목표(learning\_goal\_summary) | 이 문제에서 연습시키려는 능력입니다. | 요청 표현, 수치 비교, 근거 제시 |
| 검수상태(review\_status) | 서비스 가능한지 확인하는 값입니다. | 검수 완료, 검수 필요, 사용 보류 |
| 서비스상태(service\_status) | 실제 플랫폼 노출 상태입니다. | 노출 가능, 노출 제외, 내부 테스트 |
| 추천\_연결키(recommendation\_keys) | 비슷한 문제를 찾기 위한 기준입니다. | topic:교육, purpose:요청, grammar:-고 싶다 |
| 반복\_방지키(avoid\_repeat\_keys) | 너무 비슷한 문제를 피하기 위한 기준입니다. | scenario:상담 시간 조정, answer:미루고 싶습니다 |

## **4.3 주제 메타데이터 고정값**

주제는 콘텐츠팀이 메신저로 전달한 “종합 주제 및 세부 내용” 고정 목록을 기준으로 합니다. 해당 목록은 “국제 통용 한국어 표준 교육과정 적용 연구”를 참고한 분류입니다. 콘텐츠팀은 한 문제의 중심 상황을 기준으로 주제\_종합(topic\_main) 1개와 주제\_세부내용(topic\_detail) 1개를 먼저 고릅니다.

| 주제\_종합(topic\_main) | 주제\_세부내용(topic\_detail) 고정값 |
| :---- | :---- |
| 개인 신상 | 이름, 전화번호, 가족, 국적, 고향, 성격, 외모, 연애, 결혼, 직업, 종교 |
| 주거와 환경 | 장소, 숙소, 방, 생활 편의 시설, 가구ㆍ침구, 주거비, 지역, 지리, 동식물 |
| 일상생활 | 가정생활, 학교생활 |
| 쇼핑 | 쇼핑 시설, 식품, 가격, 의복, 가정용품 |

| 요구\_근거수(required\_reason\_count) | 2개 이상 |
| 글\_구성(required\_structure) | 서론 → 장점 → 단점 → 자신의 의견/결론 |
| 평가\_초점(scoring\_focus) | 내용, 구조, 논리, 표현 |
| 추천\_연결키(recommendation\_keys) | 장단점형, 교육 주제, 근거 제시 |
| 반복\_방지키(avoid\_repeat\_keys) | 같은 온라인 수업 논제, 같은 장단점형 연속 |

# **6\. 콘텐츠팀에서 결정하거나 확인해야 할 사항**

이 섹션은 실제 작업 전에 콘텐츠팀이 결정하거나 확인해야 하는 항목입니다. 아래 기준이 정해져야 개발팀이 안정적으로 DB 스키마와 추천 규칙을 만들 수 있습니다.

## **6.1 콘텐츠팀이 결정해야 할 사항**

| 결정 항목 | 결정 내용 |
| :---- | :---- |
| 주제 분류 기준 | 메신저로 전달된 “종합 주제 및 세부 내용” 고정 목록을 기준으로 합니다. 보조 주제는 필요한 경우에만 사용합니다. |
| 난이도\_단계(difficulty\_level) 기준 | 표준 교육과정을 참고해 내부 난이도 1\~6 기준을 정합니다. |
| 51번 빈칸\_역할(blank\_role)·빈칸\_기능(blank\_function) 값 | 일단 빈칸\_역할(blank\_role)과 빈칸\_기능(blank\_function)은 통합하지 않고 2개 값을 개별로 유지합니다. 필요하면 추후 값 사전만 보완합니다. |
| 52번 연결\_기능(connection\_function) 값 | 52번 연결\_기능(connection\_function) 값은 표준 교육과정에서 제시한 기능 값을 사용합니다. |

| 54번 글쓰기\_유형(essay\_type) 값 | 글쓰기\_유형(essay\_type) 고정값은 주장형, 찬반형, 원인·해결형, 장단점형, 기타입니다. |

| 노출 제외 기준 | 검수 필요, 표현 주의, 중복 과다 문제를 추천에서 제외할 기준을 정합니다. |

## **6.2 문제별로 확인해야 할 사항**

* 문제 번호가 올바른지 확인합니다. 51번 전용 메타데이터가 53번 문제에 들어가면 안 됩니다.  
* 주제\_종합(topic\_main)과 주제\_세부내용(topic\_detail)이 고정 목록 안의 값인지 확인합니다.  
* 글의\_목적(speech\_act)과 글\_유형(text\_type)이 실제 문제와 맞는지 확인합니다.  
* 51·52번은 빈칸\_역할(blank\_role), 빈칸\_기능(blank\_function), 대표정답(canonical\_answer), 허용정답(accepted\_answers)이 맞는지 확인합니다.  
* 53번은 자료\_유형(data\_type), 비교대상\_수(comparison\_target\_count), 핵심\_비교포인트(key\_findings)가 맞는지 확인합니다.  
* 54번은 글쓰기\_유형(essay\_type), 요구\_관점(stance\_requirement), 요구\_근거수(required\_reason\_count), 모범 답안의 글의 구조가 맞는지 확인합니다.  
* 추천\_연결키(recommendation\_keys)와 반복\_방지키(avoid\_repeat\_keys)가 너무 넓거나 너무 좁지 않은지 확인합니다.  
* 운영 태그가 문제의 사실 정보와 섞이지 않았는지 확인합니다.

## **6.3 개발팀에 전달하면 좋은 최종 산출물**

* 문제 번호별 메타데이터 입력표: 51번, 52번, 53번, 54번 시트를 분리합니다.  
* 공통 메타데이터 값 사전: 주제\_종합(topic\_main), 주제\_세부내용(topic\_detail), 글의\_목적(speech\_act), 글\_유형(text\_type), 관계(relation), 검수상태(review\_status), 서비스상태(service\_status).  
* 번호별 세부 메타데이터 값 사전: 51번 빈칸\_역할(blank\_role)·빈칸\_기능(blank\_function), 52번 연결\_기능(connection\_function), 53번 자료\_유형(data\_type), 54번 글쓰기\_유형(essay\_type) 등.  
* 태그 값 사전: 태그명, 설명, 사용 기준, 예시 문제, 사용 여부.  
* 변경 이력: 메타데이터 오류 수정, 태그 추가/제거, 노출 제외 사유.

## **7.9 추천 검색용 뷰 권장안**
