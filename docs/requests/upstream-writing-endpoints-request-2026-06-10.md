## 요청 사항

1. **문항 공급 API 신설**: admin이 완성 상태의 문항(본문·정답·메타데이터)을 수신할 수 있는 인증된 공급 엔드포인트(목록/델타 조회 또는 push-to-admin 방식 — 방식은 협의).
2. **공급 페이로드 계약**: `docs/metadata-tag-schema-rule.md` 기준 — §4 공통/번호별 메타데이터 + §7 테이블 스키마(§7.9 추천 뷰 제외, **검수 관련 필드 제외**: 검수는 공급 측에서 완료된 상태로 공급). 주제(`topic_main`/`topic_detail` — 17주제 고정 사전)·난이도(1~6)·유형·번호별 세부 메타(51 빈칸/52 연결/53 자료/54 글쓰기) 포함.
3. **idempotency 식별자**: 문항별 공급 측 고유 식별자(+버전/갱신 시각) 포함 요청 — admin은 이를 `topik_writing_question_source_map`에 매핑해 재수신 시 중복 적재를 방지(upsert)하고 역추적을 보장한다.
4. **갱신·폐기 신호**: 기공급 문항의 수정·회수(폐기) 전달 방식 — admin 측 노출 통제(`service_status`)와의 정합 협의.
5. 회신 시 admin 측은 공급 계약 스냅샷을 문서화하고(P6-1) 수신·적재 경로(idempotent upsert + `question_received` 감사)를 구현한다(P6-3).
